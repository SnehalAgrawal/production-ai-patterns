# 02-evaluation-regression

Companion code for **[LLM Evaluation: From Manual Testing to Automated Evaluation](https://snehalagrawal.com/articles/llm-evaluation-from-manual-testing-to-automated-evaluation/)** (Article #33).

It turns the hand-checked results of [01-reliable-llm-pipeline](../01-reliable-llm-pipeline/) into a repeatable evaluation, and asks two questions:

1. **Does a deterministic check agree with a person?** 01's mechanical fact check (does each expected wording appear in the reply?) against a person's judgment of the whole reply, counting missed errors and false alarms separately, plus what the check can't grade at all.
2. **What changed between two versions, email by email?** Two versions of the assistant on the same 20 test emails, with every email that went from wrong to correct or back, an exact sign test on those emails, and slices.

Part A makes no model calls. Part B ([PROTOCOL-B.md](PROTOCOL-B.md)) runs a one-sentence "friendlier" change to the drafting prompt (v4) against a fresh run of the original prompt (v3), with a local model. It also runs v3 twice, to show how much two identical runs differ.

## Run it

Python 3.10 or later (tested with 3.12.13), standard library only. No model, no network. Run from `python/`:

```bash
python check.py                     # inputs unchanged since the freeze; every reply is a text 01 labelled
python report.py --controls         # checks plus controls; prints counts only
python -m unittest -v               # tests on made-up inputs
python report.py --labels blind     # the report (refuses to run until data/blind_labels.json exists)
python report.py --labels original  # the same report against 01's hand labels
```

Reports and per-case records go to `runs/` (git-ignored). Each record carries the hash of `FROZEN.json` and of the labels file it used.

### Part B

Part B needs [Ollama](https://ollama.com) 0.40.17 with `llama3.2:3b` and `nomic-embed-text` (the IDs are in [PROTOCOL-B.md](PROTOCOL-B.md)), and 01's tokenizer in `01-reliable-llm-pipeline/data/tokenizer.json` (see 01's README). From `python/`:

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # requests and python-dotenv, pinned
.venv/bin/python run_b.py preflight      # hashes, Ollama version, model IDs, settings; no model call
.venv/bin/python run_b.py run v3a        # about 40 model calls per run
.venv/bin/python run_b.py run v3b
.venv/bin/python run_b.py reproduce      # text comparison; review before any v4 run
.venv/bin/python run_b.py run v4dev
.venv/bin/python run_b.py run v4test
.venv/bin/python run_b.py export         # data/replies-b.json
.venv/bin/python worksheet.py            # worksheet/worksheet.md and worksheet/labels.csv
.venv/bin/python import_labels.py --labeller "..."   # data/blind_labels.json
.venv/bin/python report_b.py
```

Each run waits for a shared lock and a quiet Ollama server, unloads the models before and after, and checks the server log to confirm no other client used the server during the run.

## How it works

- **Reuse, not copies.** The fact check, the label key and the matching rules are 01's own code (`score.py`, `steps.py`), imported from 01's folder. 01 is read-only here.
- **The grader's verdict per email:**
  - *pass*: every mechanical fact present;
  - *fail*: one or more missing;
  - *not gradeable*: no mechanical fact to look for.

  Human facts and questions the documentation doesn't cover are listed as not checked, never counted as passes.
- **Frozen first.** [PROTOCOL.md](PROTOCOL.md) fixes the definitions, the comparisons, the controls and five expectations before any result. `data/FROZEN.json` holds the SHA-256 of the inputs and the code that decides a result. `check.py`, and so `report.py`, stop if any of them changed.
- **Labels belong to exact replies.** A label is keyed by a hash of the email id and the reply text, as in 01. A reply that differs by one character needs a new label.

## Limitations

- **20 test emails, one model, one prompt version per arm.** Every comparison here is small. The report shows each email that changed, so a reader can see how little 20 cases can settle.
- **The fact list isn't tested.** The grader and the labels' rule refer to the same list of expected facts (01's `labels.json`, committed before any reply existed). The agreement measured is between "the expected wording appears" and a person's reading against the same facts. Whether the list is complete or correct is outside this demo.
- **Who labelled 01's replies isn't recorded in 01.** The blind labels are the human reference here. 01's labels are compared with them, not assumed to be independent.

- **The v4 development check (format and tone only; replies not read for accuracy):** v4 was not revised.

  - **Tone:** the change happened, weakly.
    - All 20 development replies changed text, and 14 of 20 changed their first line.
    - Warmth phrases appeared that v3's development replies didn't have: "thank" in 2, "happy to help" in 2, "don't hesitate" in 4, "glad" and "hope" in 1 each. v3 had none of these, apart from "feel free" in 1, as v4 did.
    - The model followed the "thank the customer" instruction in only 2 of 20 replies. The criterion for revising was "the tone change visibly didn't happen", and it wasn't met.

## Deviations from the protocol

- **D1, the labeller (2026-11-24).** [PROTOCOL.md](PROTOCOL.md) says the blind labels are written by the user. At the user's request, they were written instead by a separate Claude agent (Claude Opus 5.5, a different model family from the generator, `llama3.2:3b`).
  - **What it saw:** only `worksheet/worksheet.md`, the `labels.csv` template and 01's five help documents. It was told not to open anything else in either demo folder, and had no information about the arms, the prompt change, the grader, 01's labels or the expectations.
  - **What this changes:** the reference labels are a blind model's judgment, not a person's. Every "against the labels" result in this demo is a comparison with that labeller.
  - **Earlier draft labels, not used:** a first-pass label file was generated outside this demo by ChatGPT (reported as "GPT-6", no build identifier) from the worksheet text. It was not used, imported or compared.
